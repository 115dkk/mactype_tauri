# Gemini UI 문구 실험 결과

실행일: 2026-08-24

## 결론

이번 표본에서는 `gemini-3.7-flash`의 `low`가 가장 나았다. 짧은 UI 문구에서는
3.5와 3.6보다 번역투를 더 잘 걷어 냈고, 이미 자연스러운 문장은 그대로 두는
판단도 더 정확했다. 마이그레이션처럼 문구가 이어지는 묶음에서는 3.7
`medium`도 비교했지만, `low`보다 일관되게 나은 결과를 내지 못했다.

Antigravity OAuth 경로는 모델 비교에는 쓸 만하지만 기본 자동화 경로로는
비효율적이다. `minimal`과 Flash-Lite를 제공하지 않고, 짧은 표본에도 에이전트
문맥이 약 16K~20K 입력 토큰씩 붙었다. 반복 실행용 도구는 Gemini Developer
API에서 `minimal`을 쓸 수 있게 유지한다.

## 왜 번역에 많은 thinking이 필요하지 않았나

이번 작업은 문학 번역이나 장문의 대화가 아니다. 각 입력에는 화면 상태,
보존해야 할 기능 사실, 삭제 가능한 주장, 제품명과 플레이스홀더가 명시돼 있다.
문장 간 대명사 해소, 숨은 문화적 맥락, 장거리 서사 일관성을 추론할 필요가 없다.
모델이 해야 할 일은 제한된 의미를 짧은 UI 문장으로 다시 쓰는 것이다.

이 조건에서는 thinking을 늘려도 새로운 근거가 생기지 않는다. 오히려 내부
설계를 설명하거나 문장을 과하게 매끄럽게 만들 가능성이 커진다. 실제로 절차
13개를 한 묶음으로 비교했을 때 3.7 `medium`은 thinking 3,464토큰을 더 썼지만
대부분 `low`와 동일하거나 표현만 달랐다.

thinking을 올릴 이유가 있는 경우는 따로 있다.

- 여러 화면의 문구가 하나의 상태 전이와 롤백 계약을 이룰 때
- 한 키의 삭제가 다른 키의 안내나 버튼 가능 여부와 충돌할 수 있을 때
- 원문 자체가 모호해 코드·상태 모델을 읽어 의미를 복원해야 할 때
- 장문의 대화, 법률 문구, 문체 일관성이 이어지는 번역일 때

이번 인프라는 그래서 독립 문구를 `local`, 상태 흐름을 `flow`로 분리한다.
`flow`에는 더 많은 맥락을 주되, 명시된 사실만으로 충분하면 `low`를 유지한다.

## 측정 결과

### 독립 문구 8개, 동일한 low

| 모델 | 입력 | 출력 | thinking | 총 토큰 | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| Gemini 3.5 Flash | 15,942 | 789 | 0 | 16,731 | 보수적이지만 번역투를 자주 유지 |
| Gemini 3.6 Flash | 17,202 | 825 | 0 | 18,027 | 일부 문장이 더 관료적으로 바뀜 |
| Gemini 3.7 Flash | 15,933 | 2,534 | 1,804 | 가장 자연스럽고 불필요한 문구를 정확히 제거 |

대표적으로 3.7만 `MacLoader를 통해`를 `MacLoader로`로 고쳤고,
`AppInit 레지스트리 모드는 감지만 지원합니다`처럼 소비자에게 필요한 사실만
남겼다. 반면 원래 자연스러운 기본값 안내는 변경하지 않았다.

### 연결된 상태·마이그레이션 문구 13개

| 모델 | 입력 | 출력 | thinking | 총 토큰 | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| Gemini 3.7 Flash low | 17,191 | 1,217 | 0 | 18,408 | 채택 |
| Gemini 3.7 Flash medium | 17,199 | 4,818 | 3,464 | 의미 있는 품질 향상 없음 |

3.6 low는 Antigravity 에이전트 계층에서 두 번 실패했다. 첫 호출은 스트림이
중단됐고, 두 번째 호출은 내부 도구 메타데이터를 요구해 구조화 결과를 만들지
못했다. 이는 모델 자체 번역 능력보다 OAuth 에이전트 경로의 재현성 문제로 본다.

### 다국어 정책 전파

3.7 low 한 번으로 14개 키를 한국어·영어 외 8개 언어에 전파했다. 구조화 출력은
키, 언어, 플레이스홀더, `Control Center`, `MacTray`, `AppInit`, `UAC` 등의 필수
토큰을 모두 보존했다. 번역 결과는 차단 원인과 다음 행동은 유지하고, 정상 상태의
검증·안전 과시와 “마이그레이션 전용” 제한은 제거했다.

## 중간 검증

- 모델은 파일을 직접 수정하지 않고 제안 JSON만 생성했다.
- 키 누락, 중복, 빈 문장, 줄바꿈, 플레이스홀더 손실, 필수 토큰 손실은 전체
  결과를 거부한다.
- 제안은 한국어·영어 의미와 실제 ExecutionViewModel 상태를 다시 대조했다.
- 순수 번역투 수정은 `humanize-korean` 감사에서 A 등급, 변경률 11.18%, 보호
  토큰 100% 보존을 기록했다.
- 안전성·능력 문구 삭제는 사용자가 명시한 제품 정책 변경이므로 자연스러움
  감사와 분리하고, requiredFacts 기반 의미 검증을 적용했다.

## 적용 범위

- 한국어·영어: 자연스러움 수정 3개와 정책 문구 수정 14개
- 중국어 간체·번체, 일본어, 프랑스어, 독일어, 스페인어, 포르투갈어, 아랍어:
  같은 14개 정책 문구
- 카탈로그 전체 571개를 자동 재작성하지 않았다. 변경이 필요한 표본만 다뤘다.

PR 갤러리는 1280px 데스크톱 앱 화면의 준비 완료, 성능 저하, 마이그레이션 확인
상태를 전후로 비교한다. 휴대폰에서는 PR 본문의 세로형 섹션을 넘겨 보거나 원본
이미지 링크를 열어 확대할 수 있게 구성한다.
